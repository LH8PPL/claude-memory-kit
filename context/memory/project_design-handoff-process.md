- **Scope**: Provide one focused file + direction memo, NOT the whole repo (minimizes noise)
- **Visual references**: Include screenshots; designer judges from visuals, not code
- **Explicit constraints**: State non-negotiable requirements upfront (see Design Constraints fact)
- **Handoff brief**: Write out file paths, memo, contract reference, constraints, and specific questions
- **Validation**: Run designer output through gates and two-pass review before user judges render

**Why:** Design handoffs succeed when scope is tight, visual context is clear, and constraints are explicit—tight scope prevents noise; visuals beat code for judgment; explicit constraints prevent rediscovery of accessibility math.

**How to apply:** Use this process for any future design handoffs. Always write a brief and include screenshots. Emphasize accessibility and validation gates.
